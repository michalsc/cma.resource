# cma.resource

A small allocator for a block of memory that the CPU never caches and that is one piece in physical memory.
Part of the Emu68 ROM, next to devicetree.resource and mailbox.resource.

## Why

DMA engines and the VideoCore don't see the CPU caches, and they want buffers that are contiguous. `AllocMem()` gives you
neither. cma.resource does: what you take from it can be handed to the hardware as it is, with no cache flushing and no
scatter lists.

## How it works

The Emu68 firmware sets a zone aside at boot (the `cma` overlay), maps it uncached and announces it in the device tree
as `/emu68/cma@0`. This resource finds it there and manages it with TLSF. No overlay, no zone, and the resource simply
doesn't load.

In `user.txt`, size in MB:

```
dtoverlay=cma,size=8
```

## Using it

```c
#include <proto/exec.h>
#include <proto/cma.h>

APTR CMABase;

CMABase = OpenResource("cma.resource");
if (CMABase) {
    APTR buf = CMA_AllocAligned(4096, 64);   /* 4 KB, on a 64 byte boundary */
    if (buf) {
        /* give it to the hardware */
        CMA_FreeMem(buf);
    }
}
```

| Call | |
|---|---|
| `CMA_AllocMem(size)` | a block, or NULL |
| `CMA_AllocAligned(size, alignment)` | same, on an alignment boundary |
| `CMA_ReallocMem(buffer, size)` | grow or shrink, the data is kept |
| `CMA_FreeMem(buffer)` | give it back |
| `CMA_Avail()` | free bytes in the zone |

Details are in `Autodocs/cma.doc`. The `.sfd` is in `sfd/`; `FD/`, `clib/`, `proto/`, `inline/` and `pragmas/` are
generated by the build.

## What it costs

Uncached means slow to read. On a PiStorm, reading the zone is about 11 times slower than reading FAST RAM; writing is
as fast. Keep in it what the hardware has to share, and copy the rest.

## Building

Needs m68k-amigaos-gcc, `sfdc`, CMake, and the `devicetree.resource` submodule.

```
git submodule update --init
cmake -S . -B build -DCMAKE_SYSTEM_NAME=Generic -DCMAKE_C_COMPILER=m68k-amigaos-gcc
cmake --build build
cmake --install build --prefix <where>
```

The build produces `cma.resource.h`, the binary as a C array, to be included in the ROM (`src/boards/` in Emu68).
